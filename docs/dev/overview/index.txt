<h2 id="1-project-setup">1. Project Setup<a class="anchor" aria-hidden tabindex="-1" href="#1-project-setup">#</a></h2>
<h3 id="11-pre-requisites">1.1 Pre-Requisites<a class="anchor" aria-hidden tabindex="-1" href="#11-pre-requisites">#</a></h3>
<ul>
<li>
<p>Python (<span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>>= 3.12</span></span></code></span>)</p>
</li>
<li>
<p>Node.js (<span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>>=20.19.0</span></span></code></span>) — the PR build CI uses Node 22.21.1, the release CI uses Node 24.14.1; any version meeting the minimum should work</p>
<ul>
<li>Using versions significantly newer than the Electron-bundled Node may cause issues compiling native add-ons</li>
</ul>
</li>
<li>
<p>A lot of patience</p>
</li>
</ul>
<h3 id="12-linux-specific-pre-requisites">1.2 Linux Specific Pre-requisites<a class="anchor" aria-hidden tabindex="-1" href="#12-linux-specific-pre-requisites">#</a></h3>
<ul>
<li>Linux environments require additional dependencies, please see <a href="/docs/dev/linux-dev" class="link">Linux Specific Pre-reqs</a></li>
</ul>
<h3 id="13-windows-specific-pre-requisites">1.3 Windows Specific Pre-requisites<a class="anchor" aria-hidden tabindex="-1" href="#13-windows-specific-pre-requisites">#</a></h3>
<ul>
<li>You will need <a href="https://visualstudio.microsoft.com/downloads/" class="link">Build Tools for Visual Studio 2022</a> (Scroll all the way to the bottom)
<ul>
<li>Additionally, you need <strong>spectre-mitigated MSVC</strong>, go to "Individual Components" and select "MSVC ... - VS2022 C++ Spectre-Mitigated Libs"</li>
<li>Many native libraries do not support ClangCL well yet, hence we force it to use MSVC in our <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>.npmrc</span></span></code></span> (pnpm respects this file)</li>
</ul>
</li>
</ul>

<h4 id="161-some-points-to-note">1.6.1 Some Points to Note:<a class="anchor" aria-hidden tabindex="-1" href="#161-some-points-to-note">#</a></h4>
<ul>
<li>The <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>main</span></span></code></span> and <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>preload</span></span></code></span> processes are <strong>NOT</strong> automatically hot-loaded on edit, you need to <strong>reload the development process</strong> on each edit unfortunately
<ul>
<li>The good news is Vite bundles it <em>really really quickly</em> so it shouldnt be too big of a hassle</li>
</ul>
</li>
<li>Although the <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>renderer</span></span></code></span> process is hot-loaded, loss of states can often lead to <strong>weird errors</strong>. I recommend doing a full reload if this happens</li>
<li>Compile targets:
<ul>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>main</span></span></code></span> and <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>preload</span></span></code></span> still compile to <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>CommonJS</span></span></code></span></li>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>renderer</span></span></code></span> is <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>ESModules</span></span></code></span> only (take note when using any legacy <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>CommonJS</span></span></code></span> libraries)</li>
</ul>
</li>
</ul>
