<h2 id="2-implement-and-validate-the-fix">2. Implement and validate the fix<a class="anchor" aria-hidden tabindex="-1" href="#2-implement-and-validate-the-fix">#</a></h2>
<ul>
<li>Reproduce the defect and add the focused regression test before changing production code.</li>
<li>Make the smallest coherent fix; preserve the established architecture, test and release gates.</li>
<li>If the fix already exists on another branch, cherry-pick the exact full commit SHA and review the resulting diff. Do not cherry-pick an entire unrelated feature branch.</li>
</ul>
<h2 id="3-align-the-release-version">3. Align the release version<a class="anchor" aria-hidden tabindex="-1" href="#3-align-the-release-version">#</a></h2>
<p>Update the root, desktop and website package versions together:</p>
<ul>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>package.json</span></span></code></span></li>

<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>packages/website/package.json</span></span></code></span></li>
</ul>
<p>Update the version-bound release fixtures and run the relevant checks from <a href="/docs/dev/release/" class="link">Releasing Inkiva</a>, including <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>pnpm test:release</span></span></code></span>, the desktop version-identifier test and the official PR/package gates.</p>
