<h2 id="introduction-to-inkiva">Introduction to Inkiva<a class="anchor" aria-hidden tabindex="-1" href="#introduction-to-inkiva">#</a></h2>
<p>Inkiva is a realtime preview (WYSIWYG) editor for markdown with various markdown extensions and our philosophy is to keep things clean, simple and minimal. The application is built with TypeScript, Vue 3 and CSS on top of Electron (Muya, the editor backend, is currently still JavaScript). We use a few native node libraries and Pinia for renderer state. Inkiva can be split in three parts: the core called Muya, the main- and renderer process.</p>
<p>Muya provides realtime preview and markdown editing via multiple modules based on a block structure. You can imagine it as the editor backend with modules for markdown parsing, data store as block structure, markdown document transformations according CommonMark and GitHub Flavored Markdown specification with some extra specifications, event listeners and an exporter to generate standalone HTML and markdown files but also to generate the WYSIWYG editor. Muya is single threaded as well as Inkiva but use asynchronous functions to boost performance.</p>
<blockquote>
<p>NOTE: Inkiva's source-code editor is provided by CodeMirror and not well optimized nor feature rich. It's not part of Muya and an editor (renderer process) feature that load the markdown text from Muya (export), operate on it and re-import the text into Muya when switching to preview mode.</p>
</blockquote>
<blockquote>
<p>NOTE: Muya requires a core refactoring to provide better modularization, APIs and plugins. Furthermore, the data structure need improvements for better performance and stability.</p>
</blockquote>
<p>The editor represents the view and is split into two parts. The first is the main process that have full access to Electron and all OS features. It's mainly used for IO, user interaction with native dialogs and controlls the editor windows. The main process should not (be long) blocked by synchronous operations. The renderer process is the real editor and also a host for Muya. It's responsible for all graphical elements (<span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>src/renderer/components</span></span></code></span>), data (<span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>src/renderer/store</span></span></code></span>) and data synchronization. A renderer process is spawned for each window, operates on its own and is controlled by the main process. It contains two text editors: the realtime preview editor provided by Muya and the source-code one by CodeMirror with special features such as tabs, sidebar and editing features.</p>
<h3 id="application-entry-points">Application entry points<a class="anchor" aria-hidden tabindex="-1" href="#application-entry-points">#</a></h3>
<p>There are two entry points to the application:</p>
<ul>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>src/main/index.ts</span></span></code></span> for the main process that is executed first and only once per instance. Once the application is initialized, it's safe to access all the environment variables and single-instances and the application (<span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>App</span></span></code></span>) is started (<span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>src/main/app/index.ts</span></span></code></span>). You can use the application after <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>App::init()</span></span></code></span> is run successfully.</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>src/renderer/src/main.ts</span></span></code></span> for each editor window. At the beginning libraries are loaded, the window is initialized and Vue components are mounted.</li>
</ul>

<h4 id="opening-a-markdown-document-and-render-it">Opening a markdown document and render it<a class="anchor" aria-hidden tabindex="-1" href="#opening-a-markdown-document-and-render-it">#</a></h4>
<p><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>MarkdownDocument</span></span></code></span> is a document that represents a markdown file on disk or an untitled document. To get a markdown document you can use the <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>loadMarkdownFile</span></span></code></span> function that asynchronously returns a <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>RawMarkdownDocument</span></span></code></span> (= <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>MarkdownDocument</span></span></code></span> with some additional information) in the main process.</p>
<p><strong>Overall steps to open a file:</strong></p>
<ol>
<li>Click <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>File -> Open File</span></span></code></span> and a file dialog is shown that emit <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>app-open-file-by-id</span></span></code></span> with the editor window id to open the file in and resolved absolute file path.</li>
<li>The application (<span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>App</span></span></code></span> instance) tries to find the specified editor and call <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>openTab</span></span></code></span> on the editor window. A new editor window is created if no editor window exists.</li>
<li>The editor window tries to load the markdown file via <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>loadMarkdownFile</span></span></code></span> and send the result via the <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>mt::open-new-tab</span></span></code></span> event to the renderer process.</li>
</ol>
<ul>
<li>Each opened file is also added to the filesystem watcher and the full path is saved to track opened file in the current editor window.</li>
</ul>
<ol start="4">
<li>The event is triggered in <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>src/renderer/src/store/editor.ts</span></span></code></span> (renderer process), does some checks and create a new document state that represent a markdown document and tab state.</li>
<li>The new created tab is either opened and the <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>file-changed</span></span></code></span> event is emitted or just added to the tab state.</li>
<li>Both Muya and the source-code editor listen on this event and change the markdown document accordingly.</li>
</ol>
<blockquote>
<p>NOTE: We currently have no high level APIs to make changes to the document text or lines automatically. All modifications need user interaction!</p>
