<h2 id="insert-an-image">Insert an image<a class="anchor" aria-hidden tabindex="-1" href="#insert-an-image">#</a></h2>
<p>You can use an image command, type the Markdown syntax, paste an image or its path, or drag an image into the editor. When an image is imported, the configured insertion action determines how its file or URL is handled:</p>
<ul>
<li><strong>Copy to a local folder:</strong> store a new local file and insert a portable relative Markdown path where possible.</li>
<li><strong>Keep the original location:</strong> preserve a local path without moving that source image. Absolute paths may work on the current computer but are less portable.</li>
<li><strong>Upload:</strong> use an explicitly configured <a href="/docs/image-uploader/" class="link">PicGo uploader</a> when you want a remote image URL.</li>
</ul>
<p>Configure these options in <strong>Preferences → Image</strong>. A failed save, paste or drop must not leave a permanent <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>loading-*</span></span></code></span> placeholder in your document. Try again after correcting write permissions, the destination directory or the selected source.</p>
<h2 id="relative-asset-folders">Relative asset folders<a class="anchor" aria-hidden tabindex="-1" href="#relative-asset-folders">#</a></h2>
<p>When relative image placement is enabled, Inkiva can place new images in a folder relative to the document. Common examples are:</p>
<ul>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>assets</span></span></code></span> — a sibling assets directory</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>../assets</span></span></code></span> — a directory one level above the document</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>.</span></span></code></span> — the document's current directory</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>assets/123</span></span></code></span> — a nested directory</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>assets_${filename}</span></span></code></span> — a name derived from the current document</li>
</ul>
<p>The destination must be writable. If a saved file needs a relative asset, Inkiva resolves that destination from <strong>that file's directory</strong>, not from the application's working directory. When the document is untitled, a relative image source without a reliable document anchor cannot be resolved: save the Markdown file first or choose an available absolute/local-storage insertion action.</p>
<p>For imported files, Inkiva uses collision-safe creation so repeated pastes of similarly named images do not silently overwrite an existing asset. An image reference is inserted only after its file operation succeeds.</p>
<h2 id="edit-resize-or-repair-an-image">Edit, resize or repair an image<a class="anchor" aria-hidden tabindex="-1" href="#edit-resize-or-repair-an-image">#</a></h2>
<p>Select an image in the formatted editor to access its existing image controls. Depending on the selected image, you can change its alternative text/title, replace its source using <strong>Choose Image</strong>, or drag the resize control. A missing image can be selected to open the edit/relink tool.</p>
<ul>
<li>To <strong>relink</strong> a missing image, select the failed image. In the tested Windows v0.6.0 interface, click its image placeholder, select <strong>Embed Image</strong>, replace the existing relative path and confirm <strong>Embed Image</strong>. Other insertion modes may expose a <strong>Choose Image</strong> control. A failed import leaves the original Markdown intact and provides feedback so you can retry.</li>
</ul>
<p><img src="/docs/assets/inkiva-image-failure.png" alt="Real Windows v0.6.0 missing-image state showing the Load image failed placeholder and Embed Image replacement controls"></p>
<p><img src="/docs/assets/inkiva-image-relinked.png" alt="Real Windows v0.6.0 image successfully relinked to an existing local file with the updated relative Markdown path"></p>
<p>An isolated real-app test changed <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>![Broken image](./missing.png)</span></span></code></span> to <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>![Broken image](./correct.png)</span></span></code></span>; the image entered <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>mu-image-success</span></span></code></span> state and the new Markdown source was saved to disk without a permanent loading placeholder.</p>
<ul>
<li>Changing only alt text or title does not require re-importing or duplicating an unchanged local file.</li>
<li>An in-progress replacement should not overwrite a newer edit made while the image operation was running.</li>
<li>Switch to <strong>View → Source Code Mode</strong> to inspect or edit the exact <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>![alt](path)</span></span></code></span> syntax if the visual preview does not resolve.</li>
</ul>
<p>Images use the normal Markdown history and save/reopen flow. The editor does <strong>not</strong> automatically crawl your disk, delete unused assets or repair image paths across all workspace documents. Workspace <strong>Broken Links</strong> diagnostics are for relative Markdown <em>document</em> targets, not missing image files.</p>
<h2 id="portability-and-troubleshooting">Portability and troubleshooting<a class="anchor" aria-hidden tabindex="-1" href="#portability-and-troubleshooting">#</a></h2>
<p>If an image is visible on one computer but missing on another, inspect its Markdown path, verify the file was included when you copied the document, and prefer a relative <span data-rehype-pretty-code-figure=""><code data-language="plaintext" data-theme="github-dark-dimmed github-light" class="inline"><span data-line=""><span>assets/</span></span></code></span> folder beside your Markdown when sharing files. If you use cloud-uploaded URLs, their availability depends on the chosen external provider.</p>
